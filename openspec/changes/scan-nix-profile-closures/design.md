## Context

See proposal.md §Why and specs/security-scan/spec.md for the behavioral contract. This is a shell/jq extension of the current scanner, with the existing GitHub-script JavaScript reporting logic moved to a testable module; it is not a new vulnerability product or image pipeline.

Evidence read for this proposal: root AGENTS.md/CONTRIBUTING.md/README.md, docs/architecture.md, accepted ADR-025/023/021, docs/runbooks/build.md, nearer docs/.github/tests/images guidance, all three current Explore reports and their handover, tools/security-scan.sh, tools/cpe-map.json, both current security-scan specs, security-scan.yml/pr-lint.yml, flake.nix/flake.lock and the four package lists/profile constructor. Actual declaration counts are **8 minimal, 14 desktop, 5 installer, 7 installer-build list entries plus one separate static BusyBox output**. These are list entries, not evaluated package identities, unique union counts or closure sizes. For example, procps and dosfstools overlap lists; grub2 and squashfsTools are attribute names, not verified CPE identities.

Manifest data inspected with `jq '.nix' tools/manifest.json` pins **2.24.10**, aarch64-linux tarball URL and checksum. The external Explore inspected **2.24.0** source, establishing the full-path-keyed path-info contract for that version, not executed 2.24.10 compatibility. flake.lock currently fixes nixpkgs revision b6018f87da91d19d0ab4cf979885689b469cdd41; evaluation consumes that lock without updating it.

### Contradictions retained as facts

- ADR-025 §2 says installerBuildTools is host-only and never copied; actual Explore traces OUT_TOOLS copying and installer-build profile registration in images/installer/build.sh. Inventory follows approved actual copy provenance; this change neither edits nor endorses that copying policy. It does not assert payload survival in every installed artifact.
- Main security-scan spec prescribes per-CVE issues; active cve-hotfix-pipeline delta prescribes timestamped consolidated reports; security-scan.yml implements the stable-title durable report associated with #151. This change's scoped delta targets the main requirement and actual stable behavior. The unrelated active delta remains untouched and must not subsequently overwrite this report policy without separate owner reconciliation.
- Main clean semantics and current CVE-ID-only fingerprint omit Nix gaps. Scanner accepts absent NVD pagination fields via zero defaults; report skips malformed TSV lines. This design closes those relevant false-clean seams.
- Root/generic build guidance still contains old pin-location/Mac-fetch claims relative to accepted ADR-025/021/023. Record drift, do not rewrite guidance. Existing daily schedule conflicts with generic no-cron guidance; preserve the existing workflow/schedule, add no cron/workflow.

## Goals / Non-Goals

**Goals:** Maintain existing manifest detection while making Nix inventory, identity and mapping uncertainty durable and testable. Keep scanner logic together under one implementation owner; separate report synchronization through a frozen validated-result boundary.

**Non-Goals:** No image or init changes, pin/remediation changes, new dependencies/frameworks, ADR amendments, derivation-input inventory, whole-image SBOM, installed-target assurance, extra architecture exports, user software or non-CI channel coverage. Adding trustworthy mappings is separate curation; tools/cpe-map.json is consumed unchanged here. Missing mappings are expected incomplete coverage, not a reason to invent vendor/product aliases.

## Decisions

### 1. Read-only declaration projection and output acquisition

Create nix/security-inventory.nix as an evaluation projection accepting the repository flake, reusing its locked nixpkgs and imported lists rather than duplicating their package declarations. Project the five selected root output paths and, for the four lists plus static BusyBox, each declared package's explicit pname/version when present, drvPath, and output-name → store-path associations. Check field types; missing metadata stays null. Use the same locked input for lists and flake roots. Do not add exports to flake.nix or modify package/profile definitions. Selected buildEnv roots are explicitly recorded as generated wrappers; static BusyBox is a package, not a wrapper.

Production commands conceptually evaluate this projection with `nix eval --json --no-write-lock-file --option allow-import-from-derivation false`, then attempt selected output acquisition and `nix path-info --recursive --json` on **output paths**, per root. Evaluate via the local flake, not a moving nixpkgs/channel lookup. Treat evaluation/network/IFD refusal as an explicit acquisition gap; do not claim evaluation is fetch-free. Command flags/patch compatibility require the owner gate below.

Choose **substitution-only** acquisition: attempt `nix-store --realise <output-path> --option max-jobs 0 --option fallback false` against the existing cache.nixos.org setup, without remote builders. Missing cached buildEnv wrappers may therefore leave roots incomplete, even if member package substitutions exist. Do not invent a member-list union as a complete output closure. No source compilation, image copy or chroot action is performed by scanning. This is deliberately more conservative than running unrestricted `nix build`: slower/missing substitutions are visible, not an unbounded scheduled compile.

CI uses ubuntu-22.04-arm and the manifest .nix.binary_version/.binary_url/.binary_sha256 norm inspected in build.yml: checksum-verified tarball, copy/register its provided closure, use its absolute binaries and single-user root store with nix-command/flakes enabled. Do not copy the same setup block into a fourth site: create tools/security-scan-nix.sh with focused setup/acquisition functions; reuse the norm, leave existing build.yml blocks untouched. Setup/config remains runner-local and does not weaken image sandbox configuration. Set source-build prohibition on each acquisition command, not just one inherited variable. Do not add floating install-nix actions, cache action dependencies, persistent store caches or lock/pin bumps.

Bounds are fixed internal defaults (not new workflow/user configuration): **600 seconds total** for setup/evaluation/acquisition/metadata, per subprocess maximum **120 seconds** clipped to the remaining shared deadline; **1200 seconds total** for NVD work including pacing/backoff, maximum **200 unique Nix CPE queries**, and **35 minutes** job timeout leaving reporting margin. Manifest queries run first and retain fatal failure semantics; preflight their mappings before network work. Exhausted Nix query/time allowance marks remaining entries `not-queried-budget`; an exhausted allowance that prevents mandatory manifest processing is fatal. NVD requests retain the existing maximum 60-second timeout clipped to remaining deadline, three attempts and 5/10-second backoff. Attempt roots in a stable order and record not-attempted roots when the shared acquisition budget expires. These constants bound work, not completeness; CI measurements may motivate a separate approved tuning change.

### 2. Keyed path-info adapter and trusted identity

Accept the pinned-family **object keyed by full /nix/store paths**. Normalize with key → path, references (array of full store paths), nullable deriver and record status. Path keys, record types, reference types and optional inner path agreement are checked. A null record, missing requested root, empty response for a nonempty expected root, malformed/unsupported shape or reference lacking a returned record becomes an enumeration gap tied to the affected root; an array is unsupported, not silently converted to empty. Do not implement historical array or master --json-format adapters without evidence.

Retain graph edges and memberships per root; union paths after per-root validation. Recovery reads derivation metadata for already inventoried paths, never expands inputDrvs/inputSrcs. Trust evaluated metadata when the exact output path matches the projected association. Otherwise, for a non-null accessible deriver, `nix derivation show` must associate the current path with an actual output before accepting nonempty string env.pname/env.version. Structured env.__json is parsed only as a valid object with those explicit string fields; conflicting ordinary/structured/evaluated sources yield unknown with a conflict reason. Missing deriver, inaccessible .drv, absent/malformed fields and unverifiable output association yield unknown. Derivation name and store basename are display diagnostics only, not CPE identity or skip classification.

Supported non-package classification is narrow: exact selected profile-wrapper associations from the projection. Other runtime data/docs objects without identities remain unknown; no blanket benign classification. Record metadata source and output association even when two static/dynamic outputs share pname/version. Group query work by exact resolved CPE/version and fan results back to identity/version/path/source/root associations; do not collapse findings by CVE ID alone. Manifest effective versions do not automatically override a same-named Nix package's declared version.

Alternatives rejected: basename splitting is unauthoritative, `lib.getName/getVersion` fallbacks can disguise missing metadata, eval-only direct list scanning loses transitive references, and derivation input traversal includes build-only compilers/sources. Output verification does not prove upstream CPE identity, vulnerability applicability, or that the payload survives every installed target.

### 3. Coverage, failure and result boundary (frozen interface)

Scanner writes one UTF-8 JSON file designated by **SCAN_RESULT_FILE** (otherwise a unique temporary file outside the cleaned scanner work directory, reported to the caller and left for the caller to remove). It removes stale requested output before scanning, writes a temporary file, validates, then atomically renames only for publishable complete/incomplete results. Result file paths are passed via environment to the report; do not inject shell/Actions expressions into script source. Retain FINDINGS_TSV (six columns) and cves=true compatibility outputs for valid findings, resetting outputs at run start; JSON is authoritative for report synchronization. Missing JSON is never an empty successful scan.

#### Exact v1 wire grammar and independent side inputs

The following exhaustive grammar, plus its invariants, replaces the envelope shorthand. Every listed object key is required (including nullable keys); no other keys, duplicate JSON object keys, coerced types, non-finite numbers or unrecognized enum values are allowed. JSON is UTF-8. `S` is a nonempty string without U+0000–U+001F or U+007F; `N` is an integer 0..9007199254740991; `?T` means T or JSON null, never omitted. `P` matches `^/nix/store/[0-9abcdfghijklmnpqrsvwxyz]{32}-[A-Za-z0-9+._?=-]+$`; derivers additionally end `.drv`. `C` is the exact virtualMatchString `cpe:2.3:a:<vendor>:<product>:<converted-version>` produced by the unchanged map (not a full padded CPE). `V` matches `^CVE-[0-9]{4}-[0-9]{4,}$`. Arrays are JSON arrays; set arrays contain no duplicates. Object key order is irrelevant. Producers sort set arrays lexically by string or the key specified below; validators accept permutations and canonicalization sorts them. Empty arrays are permitted unless constrained below. Bare enum tokens in this notation are JSON strings, except boolean values and numeric schemaVersion. Producers sort roots/perRoot by id, inventory by path, manifest by id and findings by (cveId,package,version,associated cpe); validators accept reordered records but reject duplicate keys as specified below. Acquisition root order is stable independently of wire array ordering.

```text
RootId = minimalProfile | desktopProfile | installerProfile | installerBuildTools | initramfsBusybox
Surface = system-runtime | installer-image-build-payload | initramfs
Code = setup-unavailable | evaluation-failed | acquisition-unavailable | acquisition-budget |
       path-info-invalid | path-info-null | root-missing | reference-missing |
       deriver-unavailable | metadata-missing | metadata-conflict | unmapped-cpe |
       explicit-skip | query-budget | manifest-exclusion
Reason = {code: Code, detail: ?S}                     # detail only for curated skip/exclusion text
Gap = {code: Code, path: ?P}                         # root enumeration codes only, below
Identity = {pname: S, version: S, output: S, metadataSource: evaluated | deriver | structured-deriver}
Inventory = {path: P, roots: set<RootId>, references: set<P>, deriver: ?P,
             kind: package | profile-wrapper | unknown, identity: ?Identity,
             disposition: queried | profile-wrapper | unknown-identity | unmapped-cpe | explicit-skip | not-queried-budget,
             cpe: ?C, queriedVersion: ?S, reason: ?Reason}
Root = {id: RootId, surface: Surface, outputPath: ?P,
        enumeration: complete | incomplete, paths: set<P>, gaps: set<Gap keyed(code,path)>}
Manifest = {id: S, package: S, pinnedVersion: S, effectiveVersion: ?S,
            queriedVersion: ?S, cpe: ?C, disposition: queried | explicit-skip | excluded, reason: ?Reason}
Source = {type: manifest | nix, manifestId: ?S, path: ?P}
Finding = {cveId: V, package: S, version: S, score: number[7,10],
           severity: HIGH | CRITICAL | UNKNOWN, url: S,
           sources: set<Source keyed(type,manifestId,path)>, roots: set<RootId>, paths: set<P>}
Counts = {inventory: N, identified: N, queried: N, wrappers: N, unknown: N, unmapped: N, skipped: N, unqueried: N}
RootCounts = {id: RootId, counts: Counts}
ManifestCounts = {expected: N, queried: N, skipped: N, excluded: N}
Limitation = {code: Code, root: ?RootId, path: ?P, manifestId: ?S, detail: ?S}
Unscored = {cpe: C, cveId: V}
Coverage = {complete: boolean, perRoot: array<RootCounts>, global: Counts,
            manifest: ManifestCounts, limitations: set<Limitation keyed(code,root,path,manifestId,detail)>,
            unscored: set<Unscored keyed(cpe,cveId)>, unscoredCveCount: N}
Result = {schemaVersion: 1, outcome: complete | incomplete,
          scope: "locked-aarch64-output-references", roots: array<Root>,
          inventory: array<Inventory>, manifest: array<Manifest>, findings: array<Finding>, coverage: Coverage}
```

**Expected manifest set is not a producer assertion.** Each actual validator receives the result bytes AND raw manifest/CPE-map bytes loaded independently from the selected checkout: defaults tools/manifest.json and tools/cpe-map.json; an explicit caller-selected MANIFEST is passed consistently to both consumers. The report module accepts those separately loaded trusted objects as validation arguments; CI loads its own checkout files, never paths/expected rows/booleans/counts supplied in the result. Offline callers supply corpus side-input bytes. Missing/invalid side inputs fail closed before GitHub writes. This trusts checkout selection and caller control of side inputs, not scanner claims; it is consistency validation, not signed provenance or authentication of a compromised checkout/producer. Do not accept a producer-supplied digest alone as the expected-set check.

Trusted manifest side input must be an object with object-valued toolchain, toolchain.gcc_prereqs, base_packages, init_and_session, bootloader, nix and kernel; selected package entries must be objects. CPE-map side input is an object keyed by package S; every entry is exactly either `{skip:true,reason:S}` or `{vendor:S,product:S}` with optional `version_map` object mapping S keys to S values. No other entry keys or mixed skip/mapping shape is supported; vendor/product must match `^[A-Za-z0-9._-]+$`. Version-map keys/values are exact strings, not regexes or implicit aliases. Validate the entire map, including unused entries; malformed configuration is fatal. Manifest fields outside the selected extraction are not new scan inputs.

Both validators independently derive E: enumerate non-`$` keys directly under toolchain except gcc_prereqs; separately enumerate its non-`$` prereq keys; enumerate non-`$` keys under base_packages, init_and_session and bootloader; add nix.binary_version as package `nix`; add kernel.version as the explicit excluded kernel row. Each selected entry must have a nonempty string version (binary_version for nix); effective_version is absent/null or S. Unexpected non-metadata entries lacking these fields are fatal, not silently filtered. Row `id` is its exact JSON Pointer, e.g. `/toolchain/gcc_prereqs/gmp`, `/base_packages/openssh`, `/nix/binary_version`, `/kernel` (escape key `~` as `~0`, `/` as `~1`). Package is the entry key except `nix`. Exactly one manifest row per E id is required, with the independently read package/pinned/effective values; no extra/duplicate/missing rows. `/toolchain/linux_headers` and `/kernel` are `excluded` with `reason={code:"manifest-exclusion",detail:<unchanged map reason>}`, null cpe/queriedVersion; their existing reasoned skip map entries are required. Other reasoned map skips are `explicit-skip` with unchanged reason and null query fields; all others must be `queried` with null reason and exact map-derived cpe/version. Missing mappings or invalid map schema are fatal. Recounting surviving rows cannot satisfy E equality, even if all supplied counts and outcome are changed consistently.

**Versions and associations:** pinnedVersion and Identity.version are declared versions and never overwritten with a conversion. Manifest input version is effectiveVersion when nonnull, otherwise pinnedVersion; Nix input version is Identity.version (no inherited manifest override). `queriedVersion` is the map's exact version_map lookup of that input, otherwise the raw input with the existing warning on a version-map miss. It includes any update component: OpenSSH declared `9.9p1` → queried `9.9:p1` → cpe `cpe:2.3:a:openbsd:openssh:9.9:p1`. For mapped Nix entries, retain that converted value/cpe even with not-queried-budget; it describes the pending query, not a completed request. Finding.version is always the converted **actually queried** version, not the declared/effective version. A finding for OpenSSH with version `9.9p1` is invalid against that map. Rendering includes declared versions from associated manifest/inventory rows as well as the queried version. JSON Finding.version is the converted actually queried value; legacy FINDINGS_TSV keeps its existing six-column shape and pre-conversion source display version: effectiveVersion when present, otherwise pinnedVersion for manifest sources, and Identity.version for Nix sources. Construct legacy rows from source associations, not by copying JSON Finding.version; do not assume those values are equal. Preserve existing manifest legacy ordering/deduplication behavior. Thus the OpenSSH fixture has JSON finding version 9.9:p1 but legacy TSV version 9.9p1; no legacy-value migration is authorized.

Every finding has at least one source. A manifest source has a known queried manifestId and null path; a nix source has null manifestId and an existing queried inventory path. Each source's package, queriedVersion and cpe must agree with the finding's package/version and with every other source in that finding. Finding paths are exactly its nix-source paths; roots are exactly the union of those paths' inventory memberships. Manifest-only findings therefore have empty roots/paths. No orphan association, wildcard version, source inferred solely from a package name, or duplicate finding keyed by (cveId,package,version,associated cpe) is allowed; combine its exact source set instead. Finding URL is exactly `https://nvd.nist.gov/vuln/detail/<cveId>`. HIGH corresponds to score [7,9), CRITICAL to [9,10]; UNKNOWN is allowed only as the existing upstream-absent severity fallback. The boundary cannot independently prove NVD returned a row or omitted severity; producer must enforce NVD validation before construction.

**Inventory/root invariants:** inventory is unique by `path`, manifest by `id`, roots and coverage.perRoot by `id` with exactly the five RootIds. minimalProfile/desktopProfile/installerProfile have surface system-runtime, installerBuildTools installer-image-build-payload, initramfsBusybox initramfs. Each inventory.roots is nonempty. `p in root.paths` iff `root.id in inventory[p].roots`; every listed path/reference has an inventory record (missing/null upstream records remain unknown placeholders with a root enumeration gap). Every referenced path inherits the referring path's memberships. With nonnull outputPath, root.paths equals graph reachability from outputPath including that output/retained placeholders; with null outputPath, paths is empty and enumeration incomplete. Complete enumeration requires nonnull outputPath and no gaps; incomplete requires at least one gap. Gap codes are setup-unavailable/evaluation-failed/acquisition-unavailable/acquisition-budget/path-info-invalid/path-info-null/root-missing/reference-missing; null gap.path denotes root-level failure, nonnull denotes an affected path in root.paths. Absence of all inventory for an unavailable root is permitted, not a fabricated member union.

`package` kind requires Identity and disposition queried/unmapped-cpe/explicit-skip/not-queried-budget. `unknown` requires null Identity, cpe and queriedVersion, unknown-identity disposition, and reason code deriver-unavailable/metadata-missing/metadata-conflict. `profile-wrapper` requires null Identity/cpe/queriedVersion/reason, profile-wrapper disposition and exact selected outputPath association with one of the four projected buildEnv roots, never initramfsBusybox or a basename heuristic. A package queried requires exact trusted-map cpe/queriedVersion and null reason; not-queried-budget requires those same mapped values and query-budget reason; unmapped-cpe requires absent map entry, null cpe/queriedVersion and unmapped-cpe reason; explicit-skip requires map skip, null query fields and exact skip reason. Non-skip Reason.detail is null. Identity output is the verified output-name association and metadataSource has the verification meaning in §2. Where verified sources agree, prefer evaluated, then structured-deriver, then deriver; if multiple verified output names refer to that same path, choose the lexical first. Disagreement stays unknown, not precedence-based resolution. Validation checks structure/associations but does not authenticate derivation metadata.

**Recomputation:** Counts.inventory is the number of inventory rows in the selected set (perRoot membership, global unique paths); identified counts package-kind rows; queried/wrappers/unknown/unmapped/skipped/unqueried count the corresponding dispositions. The six disposition counters queried/wrappers/unknown/unmapped/skipped/unqueried partition inventory (identified is a separate overlapping count). ManifestCounts.expected is |E|, other fields count manifest dispositions; they sum to |E|. Derive coverage.limitations exactly as the deduplicated union of root gaps `{code,root:id,path,manifestId:null,detail:null}`, inventory reasons for EACH membership `{code,root:id,path:inventory.path,manifestId:null,detail}`, and manifest skip/exclusion reasons `{code,root:null,path:null,manifestId:id,detail}`. Unknown/map/query gaps can coexist with complete root enumeration. coverage.unscored lists distinct (cpe,cveId) scoreless validated NVD records for actually queried cpes, has no same (cpe,cveId) as a finding, and unscoredCveCount equals its length (shared queries counted once). This retains dropped-count reporting, not proof of NVD completeness; these diagnostic records do not affect outcome. Recompute every coverage count, limitation and association, not only totals.

coverage.complete is true iff E comparison succeeds, all five roots enumerate completely and every inventory disposition is queried or profile-wrapper. Manifest reasoned skips/exclusions are allowed scoped limitations; any Nix reasoned skip remains incomplete. outcome is complete iff that predicate is true, otherwise incomplete. Any grammar/invariant mismatch is invalid/fatal, not repaired into a publishable incomplete record. This grammar covers both complete and incomplete wire states exhaustively; expected gaps are valid incomplete, missing mandatory fields/manifest rows are not. Fingerprint substantive fields/reason codes/affected paths and curated reason text, never volatile stderr/timing/timestamps. Diagnostics stay in job logs; never expose API keys.

Exit **0**: valid complete result (findings may exist). Exit **2**: valid incomplete result. Exit **1** or an unexpected status: fatal, no publishable result/normal CI outputs. Recoverable expected Nix errors are handled explicitly and do not swallow unexpected script errors. Invalid CPE-map schema is fatal; absent Nix map entry is incomplete, while absent manifest map entry remains fatal. No map changes/aliases are part of this plan.

NVD validation requires object, integer nonnegative totalResults/resultsPerPage/startIndex, vulnerabilities array, supported first-page consistency (startIndex=0, totalResults equals returned length and does not exceed page capacity). Require each vulnerability.cve object and valid CVE ID/metrics; scoreless valid records count as dropped, malformed metric arrays/score types/ranges are fatal. Validate the entire response before extracting >=7 results; `{}`, null, arrays, truncated pages and malformed rows cannot yield clean. Do not extend to a pagination crawler.

Schema validation prevents dropped/contradictory records from being interpreted as clean within the stated independent checkout-side-input trust boundary; it does not authenticate upstream package metadata or establish NVD completeness. Both producer and report edge validate independently against this exact interface, without adding a schema-library dependency. F1 is dispositioned as one authorized contract clarification, not shadow-judge actuation; RESTRICT is retained and Apply is not authorized.

### 4. Durable report seam and CI outcome sequencing

Create tools/security-scan-report.js as a CommonJS module exposing result validation/canonicalization, pure report/action planning and async synchronization accepting injected github/core/context. Existing github-script@v7 calls that module; offline shell validators invoke it with Node and in-memory API stubs. This reuses JavaScript already present in the workflow, not a new testing language/framework. Escape markdown table/control characters and validate URLs before rendering.

Validate complete input before API mutation. Paginate labeled issues in state=all, exclude pull requests, match stable title, reuse #151 naturally by title/labels without hardcoding its number. More than one matching candidate is an ambiguity failure, not an automatic merge/close cleanup. Canonical sorted JSON includes substantive result fields/coverage; embed a new versioned security-scan fingerprint marker. Missing old marker forces one migration body refresh, not a new issue. Use Node's built-in hashing (no dependency). Status-only reopen remains a necessary action even when body fingerprint matches. No runs-as-heartbeats. Comment on meaningful added/dropped association or coverage deltas; timestamps appear only in changed bodies. When zero complete closes an open issue, write scope-qualified complete coverage; repeat closed-clean scans are quiet.

| Input/outcome | Durable action | Job result |
|---|---|---|
| valid complete with findings | create/update/reopen on meaningful delta | success |
| valid incomplete, including zero findings | create/update/reopen coverage report on delta; never close | nonzero after sync |
| valid complete zero findings | close open report; absent/already closed is quiet | success |
| fatal scan, missing/invalid result, malformed finding | no GitHub writes | failure |
| GitHub discovery/sync failure | fail, never claim successful synchronization | failure |

security-scan.yml captures scanner exits intentionally: mark publishable only for 0/2 **and validated existing result**, treat other exits as fatal. Do not put blanket continue-on-error around scanning. Sync is guarded by publishable outcome (including 2); a final status step fails after incomplete publication. Failed/cancelled acquisition that never produces validated JSON cannot trigger clean closure. Bounded setup failure must be converted into root gaps so manifest results can still yield a valid incomplete report; checksum/pin configuration corruption remains fatal. Preserve least privilege, stable resource concurrency and cancel-in-progress=false. Move issues:write to the reporting job/needed scope if splitting becomes necessary; default is one existing job, not a pipeline redesign.

Offline scenarios run in PR lint's existing deterministic job as a step, with unchanged triggers, action pins and required-check identities, plus an explicit security-scan fixture runner. They do not run image builds or boot tests. tests/security-scan/README.md documents this scoped CI invocation; image-specific build.yml test wiring guidance is not used to expand image gates.

### 5. Test and ownership plan

One shared-boundary corpus owner first materializes the §3 grammar as future valid complete/incomplete result bytes, independent raw manifest/map side inputs, and expectation index under tests/security-scan/fixtures/shared-result/. This owner alone writes that directory; no schema implementation or new fixture exists in this planning session. Corpus uses a fixed manifest snapshot covering E and the unchanged real map, including OpenSSH conversion and independent expected-row derivation; no producer-supplied expected count/boolean. Complete wire positives use synthetic graphs containing only mapped package identities plus verified root-wrapper associations; they do not assert actual static BusyBox identity, real root contents or live cache availability. Actual unmapped BusyBox stays incomplete. The integrated scanner owner still owns projection/acquisition/normalization/metadata/query/result/scenarios together, without artificial scanner decomposition. Scanner and report implementation can proceed independently only after this common prerequisite; workflow integration depends on both. Exclusive paths/dependencies are in tasks.md.

Both actual production validators (scanner result validation via tools/security-scan-result.jq and report validation via tools/security-scan-report.js), not substitute fixture-only validators, consume the identical shared valid/mutated bytes and identical trusted side-input bytes. Both accept complete/incomplete positives unchanged and reject every negative: omitted manifest row with all counts/outcome recomputed to match surviving rows; duplicate root id or duplicate path record/membership; incorrect counts or outcome; missing required nested field; orphan finding source; declared OpenSSH version substituted for converted queried/finding version. The shared positive expectation also asserts the distinct unchanged legacy TSV display version (9.9p1 versus JSON 9.9:p1); deriving TSV from JSON Finding.version must fail compatibility tests. The scanner suite asserts rejected bytes produce no result/normal outputs; report API traces for every invalid byte assert zero create/update/reopen/close/comment writes. The integrated workflow tests also prove no GitHub writes when scanner or report boundary rejects. Neither consumer rewrites shared fixtures or picks a hidden alternative schema. Consumer-specific extra scenarios remain in their exclusive scanner/report prefixes; corpus changes return to its exclusive owner.

Use thin shell GWT entrypoints in tests/security-scan/ and validators in scripts/. Scanner PATH mocks for nix/nix-store/curl/sleep and deterministic clock/deadline seams record calls, without actual realizations/network or pacing sleeps. F3 additionally requires a bounded local inert blocking process, with a child, through the actual production watchdog (only its duration shortened through the test seam): wait on deterministic child-start signal, force expiry, assert the whole process tree is terminated/reaped before result publication, no later command starts and no watchdog/child remains. Use an outer bounded safety watchdog and cleanup on failure; mere fake-clock advancement or the 35-minute CI cancellation is not this test. Node API mock traces assert writes and absences. Tests must name failing mutations:

- Drop installerBuildTools/static root, collapse versions or traverse inputDrvs → inventory scenario fails, including assertions that input-only nodes/queries are absent.
- Parse basenames or auto-skip data paths → trusted-metadata scenario fails; no inferred query permitted.
- Drop null/missing reference, accept array/empty object → keyed-normalization scenario fails and remains incomplete.
- Enable source builds, accept wrong setup version/checksum, reset the shared 600-second acquisition deadline per root or exceed the 200 unique Nix query ceiling → acquisition/budget scenario fails. Force 600-second exhaustion and remaining allowance below 120 seconds; assert clipped subprocess timeout, no later command and acquisition-budget gaps on unattempted roots. Kill/watchdog removal or killing only the parent must break the inert-process cleanup assertion.
- Reset the shared 1200-second NVD deadline, fail to clip a request below 60 seconds, or start pacing/backoff/retry beyond the remaining allowance → budget/manifest scenarios fail. Deterministically exhaust time during 7/1-second pacing and 5/10-second retry backoff, including a next sleep/request that cannot fit; assert no next request, at most three attempts, fatal mandatory manifest exhaustion with absent JSON/normal outputs, and valid Nix query-budget incomplete publication followed by report synchronization and nonzero final status. Never exceed frozen deadlines or extend them to finish retries.
- Treat Nix skip/map/identity miss as complete → incomplete-result scenario fails; no clean outputs. Force all four buildEnv wrappers unavailable while projected members are substitutable: all roots stay represented/incomplete, no member-list union or false queried disposition, no clean closure.
